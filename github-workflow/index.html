    03 / WORDS WE KEEP USING

    พจนานุกรมฉบับเรา

    Repository / repo
    พื้นที่เก็บไฟล์โค้ดพร้อมประวัติการแก้ไข
    Clone
    เอา repo ลงเครื่องครั้งแรก ได้ทั้งไฟล์และประวัติ
    Pull
    ดึงงานจาก remote แล้วรวมเข้ากับ branch ที่เราใช้อยู่ ใช้อัปเดต repo ที่มีแล้ว
    Fetch
    ดึงข้อมูลและประวัติใหม่จาก remote ก่อน ยังไม่รวมเข้ากับ branch ที่กำลังใช้งาน
    Fork
    สร้างสำเนา repo บน GitHub ในบัญชีเรา ยังเชื่อมโยงกับต้นฉบับอยู่
    Branch
    สายงานแยกภายใน repo ใช้แก้เรื่องหนึ่งโดยยังไม่เปลี่ยน main
    main
    ชื่อ branch หลักของตัวอย่างนี้ บาง repo อาจใช้ชื่ออื่น
    Commit
    บันทึกการแก้ไขเป็นเวอร์ชัน ในตัวอย่างนี้บันทึกในเครื่องก่อน push ขึ้น GitHub
    Push
    ส่ง commit ไปยัง branch บน remote เช่น GitHub
    Pull Request / PR
    คำขอให้ตรวจและรวมงานระหว่าง branch เปิด PR ยังไม่เท่ากับ Merge และไม่ใช่คำสั่ง git pull
    Merge
    รวมงานจากอีก branch เข้าสู่ branch เป้าหมาย
    Build
    ขั้นเตรียมไฟล์ก่อนเผยแพร่ บางเว็บต้องแปลงโค้ด ส่วน HTML/CSS/JS ธรรมดาอาจใช้ไฟล์เดิมได้
    Deploy
    นำโค้ดไปเผยแพร่ให้ใช้งานจริง ต้องมีระบบหรือขั้นตอนเผยแพร่ที่ตั้งไว้
    origin / upstream
    ชื่อเรียก remote ในเครื่อง origin มักเป็น repo ที่เรา clone มา ส่วน upstream ในตัวอย่างนี้ตั้งเพิ่มให้ชี้ต้นฉบับของ fork

    REMEMBER THIS

    Commit เก็บเวอร์ชัน
    Push ส่งขึ้น GitHub
    Deploy ให้คนเปิดใช้งาน

    ส่วน PR คือจุดตรวจงานก่อนรวม และ Fork คือสำเนาบน GitHub ของเรา
